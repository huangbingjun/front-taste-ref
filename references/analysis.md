# 从网页证据提炼风格

## 建立观察记录

- 先使用默认桌面视口 1440×900，再选至少三种现有页面类型补测移动视口 390×844。记录实际尺寸、最终 URL、语言、主题、时间和可见状态。视口不可调或移动类型不足时，写明限制。
- 查看截图像素，区分网页自身与 cookie 横幅、地区提示、骨架屏或拦截页。必要时观察下方区块。只操作公开的菜单、标签页或切换控件，避免改变账户或业务数据。
- 按关键元素读计算样式和边界框，记录选择器及属性。对布局测量注明视口和元素。计算出的字体栈只证明候选栈，字体是否实际加载需要额外验证。只有核对 CSS 声明确实应用到可见元素后，才能将它记为实测值。
- 有多种证据时优先结合渲染结果和 DOM。视觉尺寸可估计，但不要把截图像素和 CSS 像素混用。无法读取的图片、截图或字体留作未知。不要仅凭图像推断断点数值、悬停、焦点、动画或深色主题行为。

## 做跨页对照

| 维度 | 要找的规律 |
|---|---|
| 层级与排版 | 标题和正文的字体角色、字重和尺度对比、行宽、阅读密度 |
| 色彩与表面 | 画布、文字、分隔、主操作、信息与反馈色的角色，边框、圆角、阴影与主题变化 |
| 构图与节奏 | 容器、栅格、对齐、视觉重心、留白、内容区块交替和首屏到后续章节的变化 |
| 组件和状态 | 导航、主次操作、卡片、定价、文档目录等如何组合，实际观察到了哪些状态 |
| 图像与动效 | 产品图、插画、摄影、装饰的用途，以及可验证的运动方式 |
| 响应式 | 信息优先级、换行、折叠、堆叠、导航变化和移动交互 |

按品牌组与页面类型比较。共性至少要有两种独立页面上下文支持。重复的全站导航只能证明共享导航。证据只来自单页时按单页描述。发生冲突时先检查主题、语言、页面类型和版本，再分别记录，避免平均彼此无关的值。

## 写成下游能使用的规则

每条关键规则交代适用范围、观察、设计意图（如为推断则标记）、可执行做法和证据编号。优先解释元素的关系，例如首屏如何只给一个主行动足够的权重，产品画面如何承担解释任务，移动端先保留哪段内容。只列形容词和色值无法指导新页面。

结合用户的目标页类型给出区块顺序、组件变体、语义 token 映射和移动验收点。设计建议标明为建议。后续团队可调整品牌色、素材、字体和实际实现，在可访问性与目标产品约束下保留合适的构图和层级原则。
