# Stripe 前端风格参考

参考 [Stripe 官网](https://stripe.com/)、[开发者文档](https://docs.stripe.com/)与 [Link](https://link.com/)。2026-11-12 采集。官网首页、Payments 和定价落在新加坡英语区域，博客和文档为美国英语。证据编号对应 [来源清单](sources.json)，实测样式见 [设计变量](tokens.json)。

## 最值得迁移的设计规则

1. **把视觉强度放在区块边界。** 官网首页用右侧彩色图形衬托文字，Payments 用斜向色带把首屏接到规则网格，定价页则将方案面板叠在同类色带之上。首屏之后回到浅底和稳定的列对齐。开发时可用自己的产品视觉做一次明显的转场，之后让内容网格恢复阅读节奏。证据 E07、E09、E11、E13、E15、E17。
2. **产品叙事和方案比较用不同的组件密度。** Payments 首屏给标题、正文和操作留出一个窄列，下方四列以短标题和图标扫描价值。定价页把解释、关键价格信息、动作放在成对的大面板中，下方再用规则网格列出细节。产品页可以逐段解释价值，决策页应让关键比较同屏可见。证据 E11、E13、E15、E17。
3. **根据页面任务配置导航和色彩。** 文档首页把搜索与分组入口摆在顶部，具体文档使用常驻左侧目录、阅读区和低强调边框卡片。官网营销页的主操作更饱和，文档保持蓝紫链接与更安静的底色。把色彩当作有用途的语义变量，由页面类型选择变体。证据 E07、E15、E19、E22。

## 开发交接

给一个新的 SaaS 产品介绍页，建议按「价值标题与行动 → 说明核心工作流的产品画面 → 三至四项价值 → 客户证明或集成入口」组织页面。将标题、正文、主行动沿同一容器对齐。首页使用产品自身的色彩或图像作为视觉焦点，内容说明区恢复低对比的分隔与留白。证据 E07、E09、E11、E13。

- 主行动用实心按钮，次行动用文字链接或描边按钮。将背景、前景、圆角和焦点状态映射到项目的语义变量。选择目标产品已有的字体和素材。证据 E07、E10、E11、E14。
- 桌面用窄文本列和可读的产品画面。窄屏先保留标题、简要说明和行动，再接产品画面与价值区。比较面板采用单列，给次要导航提供可发现的入口。证据 E08、E12、E16。
- 验收时检查 1440 和 390 CSS px 下的截图。首屏应只有一个最高强调的主行动。内容网格应与前一段对齐，窄屏没有页面级横向溢出，标题和按钮无需横向滚动即可阅读。焦点可见性和对比度按目标产品要求验证。

## 覆盖和限制

本次为精简验收，登记 8 个已确认站点、30 个去重候选 URL，观察 7 个页面，其中 Link 有局部渲染缺口。截图覆盖 5 类桌面页面与 4 类窄视口页面。采集使用干净 Chrome 会话，窄视口通过调整 CSS 视口验证布局，没有模拟触摸或测试中间断点。

从官网导航、页脚、官方域名说明和 sitemap 建候选清单。官网 sitemap 提供 9 个分片，首个分片超过本次单文件读取上限。文档 sitemap 提供 5,213 条条目，候选清单按 30 条预算截断。其他区域、额外官方站点、登录后 Dashboard、动效、交互状态、深色主题和实际字体渲染均未全面验证。截图是公开页面的研究留档，其中的文字、价格及素材只用于解释版式。
