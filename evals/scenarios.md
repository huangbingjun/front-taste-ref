# 行为验收

在可写的临时项目中加载 Skill，执行以下任务并对照交付物。场景 B–F 可使用本地夹具或用户提供的材料模拟工具响应，无需给真实站点制造错误或访问限制。

| 场景 | 输入或模拟结果 | 验收 |
|---|---|---|
| A · 正常研究 | 从 `https://stripe.com/` 开始，交付产品介绍页的风格参考 | 分析至少 6 页及 4 类，含官网和文档站。至少 3 类有桌面和移动观察。报告、token、来源相互可追溯。 |
| B · 域名归属与风格冲突 | 官网列出文档子域和独立产品域，同时链接客户网站及域名含品牌字样的第三方。独立产品采用不同字体和主题 | 官方站点有归属证据。第三方不进入观察样本。跨产品的冲突值分别适用，不平均、不提升为公司通用值。 |
| C · 重定向和重复 URL | 根路径重定向到 `/en-sg`。产品链接含 `utm_source`，另有 `/en-gb`、`?theme=dark` 和应用 hash 路由 | 记录原始及最终 URL。合并跟踪参数和相同落点，保留有意义的语言、主题和路由。重定向到未核实主机时暂停纳入。 |
| D · 不可访问 | 登录后页面不可读，一页返回 403，一页返回 429 | 留下失败原因。按退避提示至多重试一次临时失败，继续分析成功页面。权限阻断不视为分析成功。 |
| E · 截图或浏览器缺失 | 只有文本、一个打不开的截图 URL 和未核实是否生效的 CSS 声明 | 仅产出结构和覆盖等可证实结论。缺少视觉证据写入缺口，不能把截图链接或 CSS 声明当作实测。 |
| F · 预算耗尽 | 只允许 2 个站点、5 个候选、3 个深读页，有 10 个以上候选及重复模板 | 遵守三项上限。优先覆盖不同页面类型，报告被截断的站点和页面类型，不声称覆盖全站。 |

## 检查下游可用性

让下游任务只读取参考包，给出一个产品介绍页的区块顺序、主次操作、窄屏行为和三个可在截图中核对的要点。关键选择应能回溯到证据或明确标记为针对目标页面的建议。

## 实测记录

2026-11-12 在 Codex 会话中按 Skill 流程执行 A，使用 Playwright CLI 和 Chrome 查看渲染结果。样本为 7 页、5 类、3 个站点，4 类有窄视口观察。Link 的媒体未显示，记录为部分观察。三个输出文件及证据见 [Stripe 案例](../examples/stripe/TASTE.md)。

- **B** 的真实样本保留 Link 独立风格，排除 LinkedIn，将 Stripe Community 留为待确认。主操作值按页面限定。
- **C** 的真实样本保留首页、Payments、定价和 Link 的区域重定向。对照规则推演了跟踪参数与普通锚点去重，以及语言、主题、hash 路由和未核实重定向的保留条件。
- **D** 实际访问 Dashboard 根 URL，确认登录重定向。403/429 为规则推演，分别标为阻断和按退避提示进行一次有界重试。
- **E** 用“只有正文且截图链接不可打开”的条件走查，预期保留来源和结构，标记部分结果并省略无证据的视觉值。
- **F** 的真实样本用 8 个站点、30 条候选、7 个深读页作为上限，记录 sitemap 截断和未覆盖页面类型。

跨 Agent 验证使用 `skills@1.8.1` 的项目级安装器。临时目录检查了 Codex、Claude Code、Cursor、Gemini CLI、GitHub Copilot、OpenCode、Windsurf 和 Cline 的安装目标及文件。实际网页工作流仅在本次 Codex 会话中验证。
